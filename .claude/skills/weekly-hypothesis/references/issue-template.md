# 週次の仮説イシューのひな形

タイトルは「何が起きているか」を短く書く（例: 「連載ページの表紙画像が大きく、LCP が『悪い』の範囲を超える」）。
「調査」「改善」だけのタイトルにしない。

```markdown
## 概要

（何が起きていて、なぜ取り組むのかを2〜3文で）

## 証拠（事実）

- （どの指標が、いつからいつまでで、どう動いたか。GA4・Search Console は前週比・割合で書く）
- （出典: Lighthouse CI の実行 URL、Search Console / GA4 の期間と条件）

## 仮説（推測）

- （原因の推測。コードやデータで裏が取れている部分と、推測の部分を分ける）

## 確かめ方

- （何をどう見れば仮説が確かめられるか）

**外れの条件:** （何が出たらこの仮説は外れと言えるか）

## やること

- [ ] （1週間で終わる大きさに切ったタスク）

## 完了の条件

- （どの指標が、いくつになったら閉じてよいか。次回の週次で確かめる）

## 関連

- #000
```
